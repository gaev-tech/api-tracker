# Облачный таск-трекер — продуктовое описание и требования

## 1. Описание

### 1.1 Проблема

- API существующих трекеров непригодны для автоматизации.
- AI-агенты не могут эффективно работать в существующих трекерах.
- Существует разрыв между разработкой и таск-менеджментом.

### 1.2 Описание продукта

Облачное приложение для управления работой через API и CLI. Распространяется как SaaS с тарифами.

## 4. Ключевые возможности

### 4.1 RSQL

4.1.1. **Назначение.** RSQL — единый язык выборки сущностей в системе.

4.1.2. **Использование в list/filter API.** RSQL используется в API-эндпоинтах для фильтрации списков сущностей.

4.1.3. **Использование в массовых операциях.** RSQL используется для выбора целевого множества в массовых операциях.

4.1.4. **Использование в условиях автоматизаций.** RSQL используется для задания условий срабатывания триггеров автоматизаций.

### 4.2 Автоматизации

4.2.1. **Назначение.** Автоматизация — правило вида «триггер → фильтр → действие», позволяющее системе выполнять операции автоматически.

4.2.2. **Фильтр.** Фильтр задаётся RSQL-выражением (см. п. 4.1.4).

4.2.3. **Триггер — событие системы.** Автоматизация может срабатывать на событие системы (создание, изменение, удаление сущности; изменение статуса задачи; и т. п.).

4.2.4. **Триггер — расписание.** Автоматизация может срабатывать по расписанию (cron-выражение или интервал).

4.2.5. **Действие — операция API.** Автоматизация может выполнить операцию публичного API системы.

4.2.6. **Действие — исходящий HTTP-вызов.** Автоматизация может отправить HTTP-запрос на внешний URL.

4.2.7. **Действие — отправка письма.** Автоматизация может отправить email-уведомление.

## 5. Доменная модель

### 5.1 Сущности

- **Пользователь.** AI-агенты работают от имени пользователя.
- **Задача.** Единица работы в системе.
- **Проект.** Контейнер задач, в который можно добавить пользователей и команды с выдачей разных прав на задачи проекта и разных прав на работу с самим проектом.
- **Команда.** Группа пользователей.
- **Событие.** Запись о факте, произошедшем в системе.
- **Токен входа.** Токен авторизации, идентифицирующий пользователя.
- **Тариф.** Набор лимитов, применяемый к пользователю.
- **Тег.** Набор текстовых значений, привязанных к одной или нескольким задачам.
- **Статус.** Состояние задачи: открыта или закрыта.
- **Автоматизация.** Правило «триггер → фильтр → действие» (детали в 4.2).
- **Блокирующая связь.** Зависимость между задачами: одна задача блокирует другую.
- **Секрет.** Конфиденциальное значение, используемое автоматизациями.
- **Прямой доступ.** Доступ на конкретную задачу, выданный пользователю или команде.
- **Проектный доступ.** Доступ на проект, выданный пользователю или команде.

### 5.2 Права

#### 5.2.1 Права задач

5.2.1.1. **Редактирование имени задачи.** Право позволяет редактировать имя задачи.

5.2.1.2. **Редактирование описания задачи.** Право позволяет редактировать описание задачи.

5.2.1.3. **Редактирование меток задачи.** Право позволяет редактировать набор меток (тегов) задачи.

5.2.1.4. **Редактирование статуса задачи.** Право позволяет изменять статус задачи.

5.2.1.5. **Редактирование блокирующих связей задачи.** Право позволяет редактировать блокирующие связи задачи.

5.2.1.6. **Редактирование исполнителя задачи.** Право позволяет менять исполнителя (пользователя) задачи.

5.2.1.7. **Выдача прямого доступа к задаче.** Право позволяет выдавать прямые доступы к задаче пользователям и командам.

#### 5.2.2 Права проекта

5.2.2.1. **Переименование проекта.** Право позволяет менять название проекта.

5.2.2.2. **Управление участниками проекта.** Право позволяет добавлять и удалять участников проекта (пользователей и команды), а также менять выданные им проектные права. Пользователь с этим правом не может выдать другому участнику больше прав, чем имеет сам в этом проекте.

5.2.2.3. **Управление задачами проекта.** Право позволяет прикреплять и откреплять задачи к проекту.

5.2.2.4. **Управление автоматизациями проекта.** Право позволяет создавать, изменять, включать, отключать и удалять автоматизации проекта.

5.2.2.5. **Импорт задач в проект.** Право позволяет импортировать задачи в проект.

#### 5.2.3 Права команды

5.2.3.1. **Переименование команды.** Право позволяет менять название команды.

5.2.3.2. **Управление участниками команды.** Право позволяет добавлять и удалять участников команды, а также менять их права. Пользователь с этим правом не может выдать другому участнику больше прав в команде, чем имеет сам.

#### 5.2.4 Владение командой и проектом

5.2.4.1. **Все права владельца.** Владелец проекта/команды имеет все права на эту сущность.

5.2.4.2. **Удаление сущности.** Владелец может удалить проект/команду.

5.2.4.3. **Передача владения.** Владелец может передать владение другому участнику.

5.2.4.4. **Удаление при выходе последнего владельца.** Если последний владелец выходит из команды/проекта, команда/проект удаляется.

## 6. Функциональные требования

### 6.1 Аутентификация

6.1.1. **Команда логина в CLI.** Авторизация пользователя инициируется командой логина в CLI.

6.1.2. **Открытие браузера при логине.** При запуске команды логина CLI открывает браузер на клиенте авторизации.

6.1.3. **Использование активной сессии браузера.** Если в браузере есть активная сессия клиента авторизации (cookie), эта сессия используется; авторизация передаётся обратно в CLI без дополнительных действий пользователя.

6.1.4. **Авторизация через magic link.** Если активной сессии нет, пользователь вводит email и получает на почту ссылку. Переход по ссылке завершает авторизацию; авторизация передаётся в CLI.

6.1.5. **Бесшовная регистрация.** Если аккаунта с указанным email ещё нет, он создаётся при первом успешном переходе по magic link. Отдельной формы регистрации нет.

6.1.6. **Единый поток для машинных акторов.** Машинные акторы (агенты, скрипты, CI) используют ту же CLI-авторизацию, что и пользователь.

6.1.7. **Один аккаунт в CLI.** Пользователь не может быть одновременно вошедшим под несколькими аккаунтами в CLI.

6.1.8. **Один аккаунт в клиенте авторизации.** Пользователь не может быть одновременно вошедшим под несколькими аккаунтами в клиенте авторизации.

6.1.9. **Логаут из CLI.** Поддерживается логаут из CLI.

6.1.10. **Логаут из клиента авторизации.** Поддерживается логаут из клиента авторизации.

6.1.11. **Независимость логаута.** Логаут из CLI и логаут из клиента авторизации — независимые действия; выход из одной точки не влечёт выхода из другой.
